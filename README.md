# BodySnatch Desktop

Подмена JS/CSS сайта локальными файлами через локальный MITM-прокси, без расширения
браузера. Работает с любым браузером, который использует системные настройки прокси.
Windows и macOS.

## Как это устроено

```
браузер ── системный PAC http://127.0.0.1:8180/proxy.pac ──┐
   хост из маски?                                          │
   ├─ нет → идёт напрямую, приложение трафика не видит     │
   └─ да  → прокси 127.0.0.1:8180                          │
        ├─ HTTPS: CONNECT → TLS с нашим сертификатом хоста
        ├─ URL подходит под маску и модуль выбран?
        │    ├─ да, файл найден → отдаём его (x-bodysnatch: mirror)
        │    └─ нет → запрос уходит на сервер как есть
        └─ WebSocket, потоковые тела, HEAD, 304 — как у обычного прокси
```

- **Перехват только по маске.** PAC строится из тех же масок, что и правила, поэтому через
  прокси идут только нужные хосты. Банки, почта и остальное не затрагиваются. Если приложение
  закрыто или упало, PAC возвращает `DIRECT` и сайты открываются как обычно.
- **Сертификат.** Корневой CA создаётся при первом запуске; закрытый ключ шифруется средствами
  ОС (DPAPI / Keychain через Electron `safeStorage`). Листовые сертификаты выпускаются на лету
  только для хостов из масок. Новый CA ограничен **Name Constraints** доменами из масок
  (`sbis.ru`, `saby.ru`…): даже при краже ключа им нельзя подписать чужой сайт. Если позже
  добавить домен вне ограничений, интерфейс предложит перевыпустить сертификат (его придётся
  установить заново); такие хосты до этого не вскрываются. CA прошлых версий остаётся без
  ограничений, пока его не перевыпустят.
- **Системные настройки.** Windows — `AutoConfigURL` в HKCU (права администратора не нужны).
  macOS — `networksetup` по всем сетевым службам (при отказе запрашивается пароль). Прежнее
  состояние сохраняется и возвращается при выходе; после аварии оно возвращается при
  следующем запуске.
- **Вышестоящий прокси.** Если в системе уже был корпоративный прокси, он остаётся запасным
  маршрутом PAC и используется для выхода наверх. Можно задать свой в «Дополнительно».
- **Live reload.** Опция «Дополнительно»: приложение следит за папками с кодом и перезагружает
  страницу (CSS обновляется без перезагрузки).
- **Движок в отдельном процессе.** Прокси, PAC и подпись сертификатов работают в Electron
  `utilityProcess` (`shell/engine-worker.cjs`), поэтому окно не подвисает, а падение движка не
  уносит интерфейс. То, что умеет только основной процесс (шифрование ключа, диалоги), движок
  запрашивает у него по IPC.
- **API недоступен из сети.** Интерфейс общается с движком через протокол `app://` и IPC. На
  порту прокси отдаётся только PAC.

## Структура

```
shell/            Electron: main.cjs (окно, трей, app://), engine-host.cjs и
                  engine-worker.cjs (движок в utilityProcess), preload.cjs
proxy/src/
  engine.mjs      сборка всего: конфиг, CA, прокси, системные настройки, API
  proxy.mjs       MITM: HTTP, CONNECT+TLS, туннель, подмена, WebSocket, live reload
  rules.mjs       маски, поиск сайта, хосты, разрешение локального файла
  pac.mjs         PAC из масок
  ca.mjs          корневой CA и листовые сертификаты
  upstream.mjs    выход наверх: напрямую или через корпоративный прокси
  fileindex.mjs   кэш проверок файлов + fs.watch
  api.mjs         маршруты API (без привязки к HTTP)
  httpapi.mjs     отладочный HTTP-сервер для API (npm start, Vite)
  platform/       win32 / darwin / unsupported: системный прокси и сертификат
  main.mjs        запуск без Electron
ui/               React + Vite
config/rules.default.json  правила по умолчанию (копируются в профиль при первом запуске)
test/             node --test
```

Данные пользователя: `%APPDATA%\BodySnatch` (Windows), `~/Library/Application Support/BodySnatch`
(macOS) — правила `rules.json`, сертификат `certs/`, журнал `shell.log`.

## Разработка

```bash
npm install
npm run dev        # Vite 5179 + Electron, DevTools открываются сами
npm start          # без Electron: прокси + API на 8181, интерфейс в браузере
npm test           # юнит- и интеграционные тесты (системные настройки не трогаются)
npm run lint       # tsc + prettier + stylelint
```

В режиме разработки (`npm run dev`, `npm run shell`) правила берутся из `config/rules.user.json`,
если он есть (файл в git не попадает).

## Релиз

```bash
npm run dist:win   # release/BodySnatch-<версия>-win-x64.exe (NSIS)
npm run dist:mac   # release/BodySnatch-<версия>-mac-{x64,arm64}.dmg — только на macOS
```

Сборка под macOS возможна только на Mac; для этого есть GitHub Actions
(`.github/workflows/release.yml`): по тегу `v*` собираются оба установщика и публикуется релиз.

**Подпись.** Сборки не подписаны. Windows SmartScreen покажет предупреждение («Подробнее →
Выполнить в любом случае»). На macOS первый запуск — правой кнопкой → «Открыть», либо
`xattr -dr com.apple.quarantine /Applications/BodySnatch.app`. Подпись и нотаризация требуют
сертификатов разработчика (Apple Developer ID, сертификат подписи кода Windows).

**macOS не проверялся на реальном Mac**: код платформенного слоя (`platform/darwin.mjs`)
написан по документации `networksetup` и `security`; первый запуск на Mac стоит пройти вручную
(сертификат → прокси → подмена).

## Firefox

Firefox хранит сертификаты отдельно. В `about:config` включите
`security.enterprise_roots.enabled`, и он начнёт доверять системному хранилищу.
