# Ревью BodySnatch Desktop 0.1.5 — 31 октября 2026

Проверены исходники движка, HTTP/HTTPS-прокси, правил, CA, платформенных адаптеров, Electron/IPC,
обновлений и React-интерфейса. Исправления внесены в исходники. Ниже отдельно указаны проверки
на Windows, проверки с подставной платформой и ограничения проверки. Установленная пользовательская
версия приложения не заменялась; публикация релиза не выполнялась.

## Оценка реализации

Основа подходит задаче: единый движок для Electron и Node, прокси в utilityProcess, общий маршрутизатор API,
PAC из тех же масок, contextIsolation и sandbox у окна, атомарное сохранение правил, ограниченный журнал
и файловый кэш. Полностью переписывать приложение не требуется.

Основной дефект архитектуры был в управлении состоянием: UI параллельно менял независимые флаги подмены
и системного PAC, а действующее состояние ОС не являлось источником для главного переключателя.
Управление теперь сосредоточено в движке; изменения выполняются последовательно, ОС перепроверяется,
ошибки не изображаются успешным включением. Общий API используют окно и внешний клиент.

## Внешнее управление

Добавлен API v1 на отдельном случайном loopback-порту с Bearer-токеном. Файл обнаружения атомарно
создаётся в профиле и удаляется при корректном выходе. Проверяются Host, токен и отсутствие браузерного
Origin/Sec-Fetch-Site; API не опубликован на порту прокси. Это не изоляция от программ того же пользователя.

Доступны состояние, правила, сайты, папки, модули, диагностика выбора файла, подмена/PAC, журнал/SSE,
CA, отдельный браузер, тема, окно, обновления и выход. Команды CA могут требовать системного подтверждения.
Обновления и окно доступны только в Electron. Контракт: [API v1](../skills/bodysnatch-control/references/api.md).

Скилл [bodysnatch-control](../skills/bodysnatch-control/SKILL.md) содержит автономный Node-клиент,
обнаружение профиля, правила частичных изменений и проверку результата. Копия установлена в
`C:/Users/Nefritor/.codex/skills/bodysnatch-control`; валидатор skill-creator прошёл.

## Границы результата

Реальная macOS, VPN/специальный профиль Chrome, системные диалоги установки и удаления CA и установка
настоящего обновления в этой проверке не проходились. Поэтому утверждать, что все платформенные сценарии
полностью проверены, нельзя. Упакованная Windows-сборка подготовлена для проверки; релиз и замена
установленного пользовательского приложения требуют отдельного выпуска.

Произвольный корпоративный PAC не вычисляется движком: автоматический upstream берётся только из
ручного HTTP-прокси; для сети с чужим PAC нужен явный upstreamProxy. Это существующее ограничение,
теперь явно указанное в README. Name Constraints — ограничение базовых доменов, не граница между
разными арендаторами внутри общего домена. Папки с кодом считаются доверенными локальными источниками,
включая используемые в них ссылки файловой системы.

Автоматическая проверка инструмента запретила удалить две временные копии CA, перенесённые старой миграцией
в первый тестовый профиль. Файлы `profile/certs/rootCA.pem` и `profile/certs/rootCA.key.enc` остались внутри
локальной папки артефактов чата. Второй профиль использовал новый независимый CA. Исходное хранилище
и файлы пользовательского приложения не удалялись.

## Дополнительный цикл 1: конкурентные операции и macOS

После основного ревью отдельно просмотрены управление PAC, сохранение, остановка и IPC.
Обновление PAC при изменении правил теперь использует ту же очередь, что включение/выключение и
проверка ОС. Повторная неудачная активация системного режима также снимает внутренний флаг подмены.

На macOS ранее выбирался первый включённый PAC среди всех служб и ручной прокси первой службы.
Теперь выбирается основная служба из Dynamic Store; состояние Wi-Fi не маскируется включённым PAC
неиспользуемого Ethernet. При остановке возвращаются только службы, в которых остался PAC данного
экземпляра: чужие изменения не перезаписываются. Снимок сохраняет и отключённые адреса PAC.
Восстановление после сбоя учитывает оставшиеся PAC на неактивных службах.

Выбор службы и избирательное восстановление проверены на моделируемых выводах scutil/networksetup.
Это дополняет проверку кода; проверка реальных настроек Mac пока ожидает подключение.

## Дополнительный цикл 2: производительность и ресурсы

- Из buildModules убраны повторные обращения к файловой системе: уже прочитанный список папок
  используется повторно. На синтетическом списке из 2000 модулей: 2000 вызовов existsSync → 0;
  один локальный замер 20,5 → 8,6 мс. Это не прогноз ускорения всего приложения.
- В off/browser движок больше не запускает системные утилиты каждые 3 секунды. Чтение state
  по-прежнему актуализирует состояние ОС; в system монитор продолжает обнаруживать внешнее отключение.
- Страховочный опрос UI приостанавливается для скрытого окна и возобновляется при показе/фокусе;
  обработчики снимаются при размонтировании.
- Вставка live-reload больше не перекодирует HTML через UTF-8: исходные байты windows-1251 и
  других совместимых с ASCII кодировок сохраняются. Проверено сравнением байтов до и после вставки.
- HTML для вставки скрипта ограничен 8 MiB. Большее тело отдаётся потоком без инъекции; проверена
  точная передача 9 MiB с chunked-ответом. Медленные SSE-клиенты отключаются при переполнении очереди,
  а очередь интерфейса и отложенные файловые события очищаются/ограничиваются.
- mac-smoke переключён на публичный локальный API без DevTools и больше не скрывает ошибку запуска
  успешным завершением шага. Добавлены существующие lint/test проверки перед сборкой Mac.

Версия package.json и package-lock.json выставлена 0.1.5. Скилл включён в репозиторий и явно указан в README.
