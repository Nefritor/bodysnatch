# BodySnatch Control

Используй Node.js 18+ и клиент из этой папки. Он читает адрес и токен из профиля, не выводит токен и возвращает ненулевой код при HTTP-ошибке или `ok:false`.

```powershell
node <папка-скилла>/scripts/bodysnatch-api.mjs GET /api/state
node <папка-скилла>/scripts/bodysnatch-api.mjs GET /api/capabilities
```

По умолчанию профиль: Windows `%APPDATA%/BodySnatch`, macOS `~/Library/Application Support/BodySnatch`. Для другого профиля передавай `--data-dir <папка>` или `BODYSNATCH_DATA_DIR`. Адрес и токен меняются при запуске. Не печатай и не публикуй `control-api.json`, заголовок Authorization и закрытый ключ CA. При отсутствии живого API клиент сам находит установленное приложение, запускает его в фоне и до 30 секунд ждёт готовности. Если приложение уже работает, используется существующий экземпляр. Не включай DevTools и не обращайся к окну для вызова команд.

Нестандартный путь приложения передавай через `--app <путь>` или `BODYSNATCH_APP` (Windows: .exe, macOS: .app). Используй установленную версию 0.1.5+. Для диагностики без запуска есть `--no-start`; ожидание запуска меняется через `--start-timeout <мс>`. Команда `/api/quit` при отсутствии живого API сразу возвращает `alreadyStopped:true`, не запуская приложение. При таймауте проверь путь, версию и профиль; не запускай повторно в бесконечном цикле.

Перед изменениями прочитай состояние. Меняй только запрошенные поля. POST `/api/config` принимает частичный объект; массивы заменяются целиком. Для папок, модуля и отдельного сайта используй специальные маршруты: они сохраняют остальные настройки. Прочитай [контракт API](references/api.md) для нужной операции.

Для JSON с путями или сложными масками записывай тело во временный UTF-8 файл и передавай `--body-file <файл>`: это устраняет неоднозначность кавычек в PowerShell. Файл с телом не должен содержать токен.

```powershell
node <папка-скилла>/scripts/bodysnatch-api.mjs POST /api/enabled '{"enabled":false}'
node <папка-скилла>/scripts/bodysnatch-api.mjs --body-file <файл> POST /api/roots
```

Главное включение — POST `/api/enabled` с настоящим boolean. Оно включает подмену и системный PAC одной командой; выключение останавливает подмену и возвращает прежний PAC. Не отправляй отдельно параллельные команды переключателя и прокси. После команды проверь `GET /api/state`: `enabled`, `routeMode`, `systemProxy.ours`, `systemProxy.overridden`, доверие и покрытие CA. После внешнего отключения системного PAC `enabled` станет false при следующей проверке (обычно до 5 секунд). Ошибка чтения ОС не означает, что прокси выключен.

Для обхода VPN есть POST `/api/browser/open`: отдельный профиль Chrome/Edge получает PAC во флаге. При `routeMode:browser` подмена работает без системного PAC. Не запускай браузер, если пользователь просил только проверить состояние. `/api/resolve` проверяет выбор файла без сетевого запроса; реальный результат подтверждай HTTP-ответом с `x-bodysnatch` и журналом, когда доступен целевой стенд.

Сертификат устанавливай/удаляй/перевыпускай только в рамках запроса пользователя на эту операцию; при системном запросе доверия или пароля пользователь подтверждает его сам. Reset удаляет ключ и закрывает приложение; новый CA создастся при следующем запуске. `quit` и установка обновления завершают приложение: потеря соединения после принятой команды ожидаема, не повторяй её автоматически. Обычная диагностика не разрешает установку обновления или удаление CA.

После записи перечитай состояние и сообщи фактический результат. При `ok:false` или ошибке прекрати зависимые действия, прочитай состояние и объясни причину; не выдавай успешно принятый запрос за проверенную подмену. Открытие/скрытие окна доступно через API, но для настройки не требуется.
